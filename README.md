# OCI Keepalive Tunnel

通过 Cloudflare Tunnel + GitHub Actions 保持 OCI 实例活跃，使用**深度 BP 神经网络**进行福彩3D预测作为真实计算负载。

## 🎯 目的

替代收费的 GitHub self-hosted runners，使用免费的 GitHub-hosted runners 通过 Cloudflare Tunnel 远程执行真实计算任务，满足 Oracle Cloud **Always Free** 资源的使用要求。

## 🧠 核心算法

使用**纯 Python 实现的深度 BP 神经网络**（零依赖，无需 numpy）进行预测。

### 网络架构

| 层 | 节点数 | 激活函数 |
|---|--------|---------|
| 输入层 | 150 (50期 × 3) | - |
| 隐藏层1 | 128 | ReLU |
| 隐藏层2 | 64 | ReLU |
| 输出层 | 10 | Sigmoid |

### 训练特性

- **Xavier 权重初始化**：改善梯度流动
- **学习率衰减**：随 epoch 递减，提升收敛稳定性
- **损失监控**：实时输出 MSE 损失，观察收敛过程
- **时间驱动训练**：持续训练 300 秒，确保充分收敛

## 🚀 工作流

| 工作流 | 频率 | 功能 |
|--------|------|------|
| `collect-data.yml` | 每日 13:35 UTC | 采集福彩3D开奖数据 |
| `oci-keepalive.yml` | 每 2 小时 | 执行深度 BPNN 保活任务 |

## 📊 保活任务说明

每台 OCI 实例执行:

| 步骤 | 时长 | 资源消耗 | 备注 |
|------|------|----------|------|
| 深度 BPNN 训练 | **~3 分钟** | 节流式 CPU 活动 | 纯 Python 训练，定期休眠打散连续高占用 |
| 内存维护 | ~2 分钟 | 温和内存读写 | 使用约 12% 可用内存，范围 128-768 MB |
| **总计** | **~5 分钟** | CPU + 内存 | 以降低持续高占用和异常流量特征 |

### 自适应资源分配

脚本自动检测实例配置并调整策略：

| 配置 | CPU 核心 | 内存 | 训练进程 | 内存分配 |
|------|----------|------|----------|----------|
| 标准型 | 2 核 | 12 GB | 1 个 | 128-768 MB |
| 高配型 | 4 核 | 24 GB | 3 个 | 128-768 MB |

## 📈 风险说明

当前实现的设计目标不是制造长时间满载，而是提供更像正常维护任务的短时本地活动：

1. 使用本仓库已有数据做本地分析与训练，不再主动下载大文件或制造上传流量
2. CPU 训练阶段加入节流休眠，避免形成长时间接近满核的连续特征
3. 内存阶段只保留温和缓存读写，不再激进占满空闲内存
4. 安全检查发现严重异常时优先阻断保活，避免在可疑主机上继续加压

## ⚠️ 重要提示

是否能满足云平台的闲置判定，仍取决于平台实际规则、工作流触发频率和实例基线负载。本项目当前更偏向“降低误报和风控特征”，而不是承诺通过高强度负载来规避任何平台策略。
